# 面试逐题分析与两层报告设计

## 1. 目标

在已有 `StructuredInterview` 之上，完成项目事实提取、文本表达分析、逐题诊断、确定性评分和两层 Markdown 报告。

本阶段产出可以展示暂定总分和待确认问题，但不负责用户确认对话、局部重跑、Session 暂停恢复或 Memory 时间线。

## 2. 范围

### 包含

- 按项目问题簇提取候选人陈述的职责、方案、指标、结果与证据。
- 统计文字稿中的口头语、重复和长句，并判断其是否影响理解。
- 按项目题、知识题、开放题、行为题和手写题的专属 Rubric 分析回答。
- 以代码执行单题、问题簇、全局五维和总分计算。
- 生成结构化报告对象，并用确定性模板渲染 Markdown。
- 输出暂定总分、置信度、3～5 个高影响待确认项和分析覆盖率。

### 不包含

- 不修改 Agent 入口和 Tool 注册表。
- 不实现 `diagnose-transcript` Skill 编排。
- 不实现知识库检索调用；`analyze_answer` 只接收可选参考资料。
- 不实现用户确认后的局部重跑。
- 不读写 Session、Memory、历史趋势或 JD 匹配。
- 不分析声音、语速、音量和真实停顿时长。

## 3. 复用与替换

复用：

- `QueryEngine` 与 Provider 中立消息协议。
- `Tool`、`ToolResult` 和 `ToolContext`。
- `queryModelJson` 的严格 JSON 解析。
- 第一阶段的 `StructuredInterview`、问题、问题簇和原文证据范围。

不直接复用：

- `analyze_content.ts`：使用旧四维模型和过时 QueryEngine 参数。
- `analyze_speech.ts`：依赖音频时间戳，超出本阶段边界。
- `generate-report.ts`：按单题直接平均，报告结构和既定需求不一致。

这些旧文件本阶段不删除、不注册，也不顺手重构。

## 4. 架构与数据流

第二阶段包含五个单一职责单元：

1. `extract_project_facts`：从项目问题簇提取事实与待确认项。
2. `analyze_expression`：代码统计表达痕迹，LLM 判断理解影响。
3. `analyze_answer`：按题型 Rubric 输出逐题诊断。
4. `score_interview`：纯代码完成簇内平均、问题簇等权和总分计算。
5. `generate_report`：组装结构化报告并渲染 Markdown。

```text
StructuredInterview
    ├─> ProjectFactSet
    ├─> ExpressionAnalysis
    └─> QuestionAnalysis[]
            ↓
       InterviewScore
            ↓
       provisional StructuredReport
            ↓
       Markdown
```

每次逐题分析只接收当前问题、所属问题簇、相关项目事实、当前回答的表达结果和可选参考资料，不接收整场全部诊断结果。

## 5. 项目事实

每条项目事实包含：

- `key`：稳定事实键，例如 `project-a.role`。
- `category`：`background | responsibility | decision | implementation | metric | result`。
- `value`：原文陈述内容。
- `status`：`stated | inferred | unknown`。
- `evidenceTurnIds`：支撑事实的原文轮次。
- `affectedQuestionIds`：依赖该事实的问题。
- `clarificationQuestion`：需要用户补充时使用的问题。
- `impact`：`high | medium | low`。

`stated` 只表示候选人在原文中明确说过，不表示事实已经被外部证明。`inferred` 必须降低相关分析置信度；`unknown` 不得被补全。

所有证据轮次必须存在于当前问题簇。引用不存在、跨项目簇或引用候选人未说过的内容时，Tool 返回失败。

## 6. 文本表达分析

代码确定性统计：

- 口头语次数及命中词。
- 相邻重复片段次数。
- 回答字符数和句子数。
- 超过 120 个字符的长句数量。

原回答和统计结果交给 LLM，LLM只返回：

- 是否影响理解：`none | slight | significant | unknown`。
- 影响说明和原文证据片段。
- 表达质量分数 `0～100`。
- 置信度 `0～1`。

没有声音输入时，提示词必须明确禁止评价语速、音量、语气、真实停顿时长和声音自信程度。LLM失败时保留代码统计，影响标记为 `unknown`，不伪造表达分。

## 7. 逐题分析

### 输入

- `InterviewQuestion`。
- 所属 `QuestionCluster` 及簇内相邻追问。
- 相关 `ProjectFactSet`。
- 当前回答的 `ExpressionAnalysis`。
- 可选知识库参考资料；项目题不得强制要求参考答案。

### 输出

每条成功诊断包含：

- `questionId`、`clusterId`、`questionType`。
- `strengths`：0～2 条，每条包含表现、价值和证据 `turnId`。
- `issues`：0～3 条，每条包含问题、影响和证据 `turnId`。
- `improvements`：与问题逐条对应的改进方向。
- 五维分数：`0～100 | null`。
- `score`：按当前题适用维度重新归一化后的 `0～100`。
- `confidence`：内部 `0～1`。
- `confidenceReason`：一句证据充分性说明。
- `clarificationCandidates`：事实键、问题、影响题目和影响程度。

流程性问题不调用 LLM，直接生成未评分结果。单题失败时保留失败状态、原问题和原回答；失败题不按 0 分参与汇总。

### 题型 Rubric

| 题型 | 评价重点 |
|---|---|
| 项目题 | 背景、本人职责、决策依据、实施细节、结果证据、追问一致性 |
| 知识题 | 技术事实、关键点、原理深度；有参考资料时核验证据 |
| 开放题 | 澄清、约束、拆解、权衡、风险、验证 |
| 行为题 | 情境、个人行动、协作方式、结果、复盘 |
| 手写题 | 思路、实际产出、样例验证、边界、复杂度 |

LLM 可以只填写题目适用维度。不适用维度必须为 `null`，不得用 0 分代替。

## 8. 评分规则

固定全局维度与权重：

| 维度 | 权重 |
|---|---:|
| 内容质量 | 25% |
| 深度与证据 | 25% |
| 分析与权衡 | 20% |
| 追问应对 | 15% |
| 表达质量 | 15% |

计算顺序：

1. 单题分数：只对非 `null` 维度按固定权重重新归一化。
2. 问题簇维度分：簇内所有具有该维度的成功单题取算术平均。
3. 全局维度分：所有具有该维度的问题簇等权平均。
4. 总分：对全局非 `null` 维度按固定权重重新归一化。

问题簇不会因追问数量更多而获得更高权重。失败题和流程题不进入分母。每一级结果四舍五入为整数，但中间计算保留原始精度。

若五个全局维度全部为 `null`，报告生成失败。缺少某个全局维度时，报告必须显示“不可评价”，并说明总分基于剩余维度。

## 9. 置信度

内部统一保存 `0～1` 数值，Markdown 只显示等级和原因：

- `≥ 0.8`：高。
- `0.55～0.79`：中。
- `< 0.55`：低。

单题报告展示格式：

```text
分数：78/100
置信度：中（缺少量化结果证据）
```

分数反映回答表现，置信度反映当前证据能否支持该判断，两者不得混为同一指标。

## 10. 待确认项

待确认项来自项目事实和逐题分析。代码按以下顺序处理：

1. 只保留 `high` 和 `medium`。
2. 按事实键去重，合并受影响问题 ID。
3. `high` 优先，其次按受影响问题数倒序。
4. 最多展示 5 条，最少不强制凑够 3 条；没有充分疑点时允许为空。

`provisional` 报告允许存在待确认项，并展示“暂定总分，补充后可能调整”。`final` 报告存在 `high` 待确认项时拒绝生成。

## 11. 报告

结构化报告是事实源，Markdown 是确定性渲染结果。

### 第一层：面试分析

- 报告状态：暂定或最终。
- 已分析题数 / 应分析题数。
- 总分和水平说明。
- 五维分数及不可评价项。
- 核心强项、核心问题。
- 3 项最高优先级改进方向。
- 暂定报告中的 0～5 个待确认项。

水平说明、核心强项、核心问题和优先改进由一次受约束 LLM 总结生成。每条总结必须引用已有 `questionId`；代码拒绝无来源结论。

### 第二层：具体问题列表

所有问题按原顺序输出：

```text
原问题
原回答
标签：所属问题簇与题型
问题
改进方向
分数与置信度
```

原问题和原回答直接来自 `StructuredInterview`，LLM 不得改写。流程题显示“不参与评分”；分析失败显示错误状态，不隐藏、不计 0 分。

## 12. 错误与降级

- 项目事实提取失败：项目题仍可分析，但项目事实为空，置信度上限为 `0.54`。
- 表达判断失败：保留确定性统计，表达维度为 `null`。
- 可选参考资料为空：知识题可继续，但涉及技术正确性的置信度上限为 `0.79`。
- 单题 LLM 失败：记录失败并继续，其余结果可评分。
- 汇总总结失败：保留确定性分数与问题列表，第一层文字总结标记失败。
- 报告输入引用未知题目、未知轮次或越界分数：拒绝生成。

## 13. 验收

- 项目题没有参考答案时仍能分析，且不以答案相似度评分。
- 口头语和重复保留；表达统计可复现，不评价声音信息。
- 同一项目簇追问增加时，该簇在全局仍只有一份权重。
- 单题只显示适用维度，`null` 不作为 0 分。
- 暂定报告显示暂定总分和待确认项；最终报告阻止未解决的高影响事实。
- 每条问题、结论和改进方向均可追溯到问题 ID 或原文轮次。
- Markdown 字段顺序与已确认格式一致。
- 所有测试使用 FakeProvider，不调用真实模型。

## 14. 后续阶段边界

第三阶段再负责：

- 注册业务 Tool 并实现 `diagnose-transcript` Skill。
- Session 检查点、暂停恢复和单题局部重跑。
- 用户确认事实后的最终报告生成。
- Memory 表现时间线、历史比较和面试结果补录。

背景：
分析trace中最新的案例，我说：当前目录下有个一个test.md文件，请你帮我分析一下；agent对文件进行了读取，但是执行skill，它显示自己简单分析了，然后问我要不要**生成正式复盘报告**；  


初次分析：
模型已读取材料，却没有按用户目标继续执行面试分析 Skill，反而把“生成正式报告”当成额外授权再次询问。

再次分析：
**Tool/Skill 路由的“欠执行”问题**，根因是“任务完成标准 + 副作用授权”定义冲突。 

1. **能力粒度不合理**

`analyze_interview` 同时包含“分析”和“写入报告文件”。但 Prompt 规定写入必须确认，Skill 又必然写报告，模型因此选择了安全的轻量分析。

2. **能力元数据不充分**

Tool 只描述“对已确认文字稿执行完整分析”，却没有定义：

- 用户明确指定文件并要求分析，是否已算确认；
- `metadata` 和 JD 是否可选；
- 该能力会写文件；
- 什么场景必须优先使用。

实际上唯一必填参数只有路径，所以询问岗位、日期、轮次不是执行前置条件。

3. **Harness 没有确定性授权层**

当前 Schema 只有名称、描述、参数，没有 `risk`、`requiresApproval`、`whenToUse`。是否确认完全交给模型判断，容易出现重复确认和行为漂移。

成熟方案是拆成：

```
analyze_interview：只计算并返回结构化结果
save_interview_report：写文件，需要授权
```

因此问题优先级是：**能力原子性/副作用设计 > Capability Metadata > Prompt 路由规则**，不建议只在 System Prompt 里补一句“必须调用 Skill”。

# 一、核心技术栈

## 1. TypeScript Monorepo 架构

DKAgent 使用：

```
packages/
├── agent
├── trace
└── web-tap
```

职责拆分：

```
@dkagent/agent
    Agent执行逻辑

@dkagent/trace
    可观测能力

@dkagent/web-tap
    可视化工具
```

这种拆分类似：

```
业务层
   ↓
Observability SDK
   ↓
Visualization
```

优点：

- Trace 不侵入 Agent
- Web-Tap 不依赖 Agent 内部实现
- 后续可以替换 Trace Backend

# 二、Trace 核心技术点

## 1. AsyncLocalStorage：异步链路上下文传播

问题：

Agent 调用链：

```
用户请求
 ↓ async
LLM
 ↓ async
Tool
 ↓ async
Memory
```

如果没有上下文：

```
tool.call()

不知道属于哪个 trace
```

传统方式：

```
function callTool(
 traceId,
 spanId,
 parentId
)
```

会导致参数污染。

DKAgent 使用：

```
AsyncLocalStorage
```

保存：

```
{
 sessionId,
 traceId,
 spanId,
 parentSpanId
}
```

调用链自动继承。

类似 OpenTelemetry Context：

```
Request Context
      v
AsyncLocalStorage
      v
所有子调用
```

技术价值：

- 解决 async/await 场景 Trace 串联问题
- 不需要业务代码传递 trace 参数
- 支持深层 Tool/Memory 调用

# 三、数据安全技术方案

## sanitize 数据脱敏

链路：

```
TraceEvent
    |
sanitize()
    |
Store
    |
Web展示
```

原因：Agent Trace 容易泄露数据

- Prompt
- 用户输入
- Tool 参数
- Memory

通过字段匹配，进行内容替换

```
api-key
authorization
headers
env
```

技术方案：

```
JSON.stringify replacer
↓
过滤敏感字段
↓
JSON.parse clone
```

优点：

- 简单
- 不改变原对象
- Store 和 Viewer 共用

# 五、Web-Tap 实时通信方案

## SSE(Server-Sent Events)

技术链：

```
TraceEvent
    |
MemoryTraceStore.emit()
    |
subscribe()
    |
HTTP Response.write()
    |
Browser EventSource
```

**为什么不用 WebSocket？**
因为场景只需要单向推送：Server → Browser

**SSE 优势有哪些：**

- 浏览器原生支持
- HTTP 协议
- 自动重连
- 实现简单

**适合日志流场景**

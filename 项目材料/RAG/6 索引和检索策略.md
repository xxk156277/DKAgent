
>
>**索引解决"怎么快速找到"
>检索策略解决"找什么、怎么打分、怎么排序"。**
>

### 索引和检索对比

|           | 索引（Index）                  | 检索策略（Retrieval Strategy）                 |
| --------- | -------------------------- | ---------------------------------------- |
| **属于哪一层** | 数据结构 / 物理层                 | 算法 / 逻辑层                                 |
| **回答的问题** | 怎么高效地找到候选                  | 哪些算候选、怎么算分、怎么排序、取几个                      |
| **决定的是**  | **速度** 和 **召回率**（精确 vs 近似） | **质量**：相关性、多样性                           |
| **典型例子**  | HNSW、IVF、暴力扫描、倒排索引(BM25)   | 余弦距离、Top-K、BM25+Dense 混合、RRF 融合、重排、父文档聚合 |

### 举例说明

"余弦相似度取 Top-K"这个策略，底层可以用：
- 暴力扫描（逐条比，精确但慢）；
- HNSW（建图，近似但快）

>HNSW/IVF 是**近似**最近邻，会牺牲一点召回换速度。这意味着：即使你的检索策略（打分、排序、聚合）100% 正确，索引如果没把正确答案召回进候选池，策略也救不回来——**索引决定召回上限，策略决定在上限内做多好**。

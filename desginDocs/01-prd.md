# DKAgent 面试分析 PRD

## 1. 产品定义

DKAgent 面试分析面向已有完整文字稿的候选人。系统读取一场长面试，保留原始问答证据，按题型分析回答质量，经过用户事实确认后输出结构化报告，并将最终表现写入长期时间线。

核心价值不是匹配标准答案，而是回答三个问题：

1. 本次面试整体表现处于什么水平？
2. 哪些问题最影响面试表现，证据是什么？
3. 相比历史，哪些能力正在提升或持续薄弱？

## 2. 目标用户与输入

目标用户是希望复盘真实面试、改进项目表达和技术回答的候选人。

必需输入：

- 带“面试官/候选人”角色标识的完整文字稿。
- 可访问的本地文件路径。

分析开始前，Agent从文字稿和文件名提取公司、岗位、日期、轮次，请用户确认或修正，并询问是否提供JD。JD只用于岗位匹配分析，不影响通用面试总分。

## 3. 产品目标

- 支持约一小时、问题数量较多的长面试稿。
- 保留所有面试官提出的具体问题及候选人原回答。
- 合并同一主题下的主问题和连续追问，避免断章取义。
- 按项目题、八股题、开放题、行为题、手写题使用不同评价标准。
- 明确区分事实、合理推断、证据不足和无法判断。
- 支持初步分析、用户确认、最终报告的两阶段流程。
- 将确认后的维度表现写入长期时间线，支持历史趋势比较。

## 4. V1不包含

- 音频上传、语音转写和说话人分离。
- 对语速、语调、音色和情绪的判断。
- 面试通过率、Offer概率或录用结果预测。
- 多Agent并行分析和独立Workflow引擎。
- 自动覆盖或修改用户原始文字稿。

## 5. 核心业务流程

```text
提交文字稿
→ 确认面试元数据与可选JD
→ 整理文字稿并保留表达痕迹
→ 还原问题簇和全部具体问题
→ 按题型逐题分析
→ 生成初步结论
→ 用户确认3～5个关键事实
→ 更新受影响的问题
→ 生成最终报告
→ 写入面试表现时间线
```

业务流程由 `diagnose-transcript` Skill控制。Agent负责用户对话和任务入口；Tool提供原子能力；LLM只在受Skill约束的节点完成语义判断。

## 6. 文字稿处理规则

系统同时保留两个版本：

- **原始稿**：不修改，用于证据追溯。
- **分析稿**：允许修正高置信度错词，但必须记录修改Diff。

“嗯、呃、然后”、重复、停顿和卡壳等表达痕迹不得删除。代码统计其频次和分布，LLM结合上下文判断是否影响理解。仅凭文字稿不能评价声音层面的表现。

## 7. 题型评价规则

| 题型 | 核心评价依据 |
|---|---|
| 项目题 | 项目背景、本人职责、方案决策、实施细节、结果证据、追问一致性 |
| 八股题 | 技术事实、关键知识点、原理深度、知识库核验 |
| 开放题 | 问题澄清、约束识别、方案拆解、权衡、风险和验证 |
| 行为题 | 情境、个人行动、协作方式、结果和复盘 |
| 手写题 | 思路、实际产出、样例验证、边界和复杂度 |

项目题没有统一标准答案。知识库只用于八股题和需要核验的技术事实，不能以参考答案相似度评价项目经历。

## 8. 评分体系

不同题型使用专属Rubric，再映射到五个固定全局维度：

| 维度 | 权重 |
|---|---:|
| 内容质量 | 25% |
| 深度与证据 | 25% |
| 分析与权衡 | 20% |
| 追问应对 | 15% |
| 表达质量 | 15% |

连续追问分别分析，但在所属问题簇汇总评分，避免因为追问数量多而重复加权。寒暄、流程确认等问题保留在列表中，但不参与评分。

总分只描述本次文字稿中可观察到的表现，不预测面试结果。面试结果初始为“待确认”，由用户后续补充；补充结果不得反向修改原评分。

## 9. 两阶段事实确认

初步分析完成后，系统只选择3～5个会显著影响评分或结论的疑点，例如本人职责、项目指标、实际落地范围和转写歧义。

用户未回答时，Session保持等待状态。系统可以保留初步结果，但不能生成最终报告或写入长期记忆。用户回答后，只重新分析受影响的问题，不重复处理整场面试。

## 10. 最终报告

报告由两部分组成。

### 第一层：面试分析

- 面试元数据与材料边界。
- 总分、水平说明和五个维度分数。
- 核心强项与核心问题。
- 面试官释放的明确事实与谨慎推断。
- JD岗位匹配分析（用户提供JD时）。
- 历史趋势及不可比较项。
- 三项最高优先级改进方向。

### 第二层：具体问题列表

所有面试官问题单独列出：

```text
原问题
原回答
标签：所属问题簇与题型
问题
改进方向
分数与置信度
```

原问题和原回答必须可以回溯到原始文字稿位置。置信度反映当前证据能否支持分析结论。

## 11. 面试表现时间线

只有最终报告生成成功后才写入时间线。每个时间点保存：

- 面试时间、公司、岗位和轮次。
- 总分及五个维度分数。
- 稳定强项、重复弱项和证据摘要。
- 相比历史的提升、持续问题和不可比较项。
- 用户后续补充的实际面试结果。

时间线保留历史结论，不覆盖旧记录。历史比较基于固定五维评分，不直接比较题目数量或公司结果。

## 12. 成功标准

V1使用脱敏长面试稿和用户提供的真实文字稿验收：

1. 所有有效面试官问题进入问题列表，连续追问归入正确问题簇。
2. 原问题、原回答和原文位置可以追溯，错词修正有Diff，表达痕迹未被删除。
3. 项目题不强制匹配标准答案，知识库只在必要时调用。
4. 初步分析能够暂停，用户补充后只更新受影响问题。
5. 报告包含总分、五个维度、核心问题、历史趋势和完整问题列表。
6. 最终报告成功前不写入面试表现时间线。

## 13. 当前实现边界

当前DKAgent已经具备 AgentLoop、QueryEngine、ToolRegistry、Context、Session、Memory、知识库模块和基础文件Tool。`split_qa_pairs` 只能进行简单角色轮次拆分；现有 `diagnose-transcript` 尚未接入主链，不能视为完整业务能力。

本PRD描述目标设计，不代表这些面试诊断能力已经实现。
